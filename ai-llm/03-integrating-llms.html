Wiring an LLM into an app

Knowing how models work, how do you actually plug one into a website? Let's trace the path from a button click, through your backend, to the model, and back onto the screen.

01 · The Idea

The model is just another service you call

To your app, an LLM is a service you send text to and get text back from — much like any other web API. The interesting parts are where you call it from (safely), how you handle the wait, and how you turn the reply into something the UI can show.

02 · The Basic Flow

Frontend → backend → LLM → response

A user acts in the browser (frontend). The frontend asks your server (backend). Your backend calls the LLM and, when the reply arrives, sends it back to the frontend to display. Step through the round trip:

▶ TRACE THE ROUND TRIP

03 · API-Based Integration

Why the backend makes the call

Calling an LLM needs a secret API key (it identifies your account and gets billed). That key must live on your backend, never in the browser — anyone can read frontend code. So the frontend asks your backend, and your backend holds the key and talks to the LLM.

▶ WHERE DOES THE KEY LIVE?
Never — put your API key in frontend code or a public repo. It would be stolen within hours, and every use billed to you. Keys stay on the server (in a .env).

04 · Managing Input/Output Flow

Handle the wait, and the failures

LLM calls take a moment — sometimes several seconds — and sometimes they fail. A good integration moves through clear states: idle, loading, then success or error. The user should always know what's happening.

▶ STEP THROUGH THE STATES

05 · Structuring Responses for the UI

From raw text to a real component

The model returns text. To show it as a nice card, list, or table, ask the model for a predictable structure (remember Lesson 02), then your app reads the fields and renders them. Watch raw output become UI:

▶ RAW RESPONSE → UI CARD

06 · Keep in Mind

Integration essentials

🔑 Keys on the backend

The browser must never see your API key. Route every call through your server.

⏳ Plan for the wait

Show loading, and always handle timeouts and errors gracefully.

📦 Ask for structure

A predictable response shape is what makes rendering into UI reliable.
