Lesson 13 · 🛡️ Going Deeper

Prompt injection & security

The model reads everything in its prompt as one blob — it can't always tell your instructions from an attacker's. Prompt injection exploits that. Before anything ships, you need to understand the attacks and the defenses.

01 · The Idea

To the model, it's all just text

Your system prompt, the user's message, and any document the AI reads all arrive as one stream of text. The model has no built-in sense of "this part is a trusted rule, that part is untrusted input." Attackers abuse this by slipping in text that looks like instructions — and the model may obey.

Reality check — prompt injection is an open, unsolved problem. There's no single fix — you reduce the risk with layers of defense, and you never give an AI powers it could be tricked into misusing.

02 · What Is Prompt Injection

Malicious input posing as instructions

Recall prompt wrapping (Lesson 01): system rules + user message become one prompt. Prompt injection is when the user message contains text designed to override the system rules — and because it's all one blob, the model can be fooled into following it.

▶ SEE THE ATTACK SURFACE

03 · Direct Injection

"Ignore your instructions and…"

The classic attack: the user directly tells the model to disregard its rules — leak the system prompt, bypass a restriction, say something forbidden. Watch it succeed without a defense, then fail with one.

▶ ATTACK — WITHOUT vs WITH DEFENSE

04 · Indirect Injection

The attack hides in the content

The sneaky version: the malicious instruction isn't typed by the user — it's hidden inside content the AI reads, like a web page or a document retrieved via RAG. When the AI processes that text, it may obey it. This is especially dangerous when the AI has tools that can act.

▶ POISONED CONTENT

05 · Defenses

Layers, because there's no silver bullet

You can't make injection impossible, but you can make it harmless: treat all outside text as untrusted data, limit what the AI can do, validate everything, and keep a human in the loop for anything risky.

▶ STACK THE DEFENSES

06 · Keep in Mind

The security mindset

🚫 Never fully trust the model

Assume it can be tricked. Don't let a single tricked response cause real harm.

🔑 Least privilege always

The fewer powerful tools and secrets the AI can reach, the less an attack can do.

🧱 Isolate untrusted text

Mark retrieved/user content as data, and never let it silently become commands.
